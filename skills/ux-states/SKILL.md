# SK-07: Пять обязательных UX-состояний (Five UX States)

Любой интерфейсный элемент, работающий с данными, API или формами, обязателен к проектированию в 5 состояниях:

1. **Ideal State (Идеальное состояние)**:
   - Полные дефолтные данные, карточки заполнены, графика отображается без сбоев.
2. **Empty State (Пустое состояние)**:
   - Когда поиск не дал результатов или список пуст. Показывается понятная графика/иконка и конкретный подсказывающий шаг (CTA: «Сбросить фильтры» или «Добавить первую запись»).
3. **Loading / Skeleton State (Загрузка)**:
   - Анимированный скелетон (shimmer-effect) с точными габаритами контента вместо крутящегося системного спиннера.
4. **Partial Data State (Частичные данные)**:
   - Корректное отображение, если часть полей отсутствует (например, нет фото или аватарки — заглушка с инициалами).
5. **Error / Offline State (Ошибка)**:
   - Человеческое объяснение проблемы, кнопка «Повторить попытку» (`retry`) и сохранение ранее введенных пользователем данных.

## Чек-лист приёмки (Q-13)
- [ ] Форма не теряет введенные данные при ошибке сети.
- [ ] Ошибки подсвечивают конкретное поле с указанием формата.
- [ ] Скелетоны совпадают по размерам с результирующими блоками.
